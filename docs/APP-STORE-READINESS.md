# Mac 배포 준비 현황

2026-09-22 · 그래프 워크스페이스 변경의 배포 검토. 이 문서는 출시 완료나 Apple 심사 통과를 뜻하지 않는다.

## 배포 경로

현재 코드는 Apple Silicon용 일반 Electron 앱을 만든다. `release:mac`은 Developer ID 서명과 공증을 요구하는 직접 배포 경로다. Mac App Store는 별도의 MAS 빌드, App Sandbox, 배포 인증서와 provisioning을 요구한다. 기존 Chromium renderer sandbox가 Apple App Sandbox를 대신하지 않는다. [Electron 공식 제출 안내](https://www.electronjs.org/docs/latest/tutorial/mac-app-store-submission-guide)

현 제품은 로컬 Docker/PostgreSQL과 Git·CLI 프로세스에 의존한다. Mac App Store의 자체 포함·샌드박스 및 외부 설치 관련 요구와 이 구조의 호환성을 실증하지 못했다. 인증서를 붙이는 것만으로 해결된다고 볼 수 없다. [Apple 심사 지침 2.4.5](https://developer.apple.com/app-store/review/guidelines/#hardware-compatibility)

권고: 기존 직접 배포용 품질 검사를 유지하면서, 스토어 배포는 실행기 분리 여부를 먼저 결정한다. 원격 실행기는 인증·네트워크·운영 비용을 추가하므로 이번 UI 개선에서 임의로 도입하지 않았다.

## 이번 UI 변경의 품질 기준

- 에이전트 이동은 편집 초안에만 반영되고 저장 시 기존 승인 binding 규칙을 따른다.
- 진행 중 실행 또는 종료 미확인 상태에서는 흐름 편집을 잠근다. 공유 표준은 기존 패키지 편집 경로로 관리한다.
- 실행 그래프는 선택한 실행과 시도에 한정하며 완료·실행 중·결과 미확인을 분리한다.
- AI 초안은 설정한 연결에 명시적으로 요청한다. 입력한 역할과 단계만 보내며 저장된 키를 화면이나 오류에 반환하지 않는다. 도구 실행이나 승인 권한은 없다.
- 문서/단위/DB/브라우저/접근성/패키지/독립 리뷰의 실제 결과는 `VERIFICATION.md`에 기록한다. 이 목록 자체가 통과 증거는 아니다.

공개 출시의 남은 항목은 별도의 운영/인증/실기기 증거가 필요하다. 미검증 항목을 ‘스토어 출시 수준 완료’로 일괄 표시하지 않는다.
