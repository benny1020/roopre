## 확인한 불변 조건

- 필수 검토자의 7개 검토 항목과 전원 승인이 없으면 직접 API 실행 요청도 거절한다.
- 작성자·에이전트·외부 fixture ID는 검토자 승인을 대신할 수 없다. 작성자와 독립된 검토자가 적어도 한 명 필요하다.
- 차단 의견은 작성자가 수정 완료 표시를 해도 검토자의 해결 확인 전까지 남는다.
- 새로운 설계, 승인 철회, 추가 차단 의견, 지침·의존성 변경은 승인/실행 가능성을 재평가한다.
- 이전 설계 본문·해시는 보존하고 이전 버전 댓글은 그 버전에 계속 연결한다.
- 동시 초안 저장 두 건 중 하나만 커밋되고 다른 하나는 409 충돌을 받는다.
- 동일 요청 ID 재시도는 원래 응답을 돌려주며 이벤트를 중복 생성하지 않는다. 다른 내용/사용자로 ID를 재사용하면 거절한다.
- 상태·이벤트·명령 응답은 한 DB 트랜잭션에 기록한다. 저장소 객체 재생성 후 상태와 revision이 보존된다.
- 두 SSE 구독자에게 커밋 이벤트가 전달되며 cursor 기반 재구독으로 이후 이벤트를 재생한다.
- 실행 요청의 적용 지침 본문은 후속 정책 변경으로 덮어쓰지 않는다.

## 브라우저에서 실제 수행한 흐름

CUA의 브라우저 자동화와 DOM/스크린샷을 사용했다. 로컬 API/DB에 연결한 두 브라우저 탭, 개발용 준·민아·소라 계정으로 수행했다. 실제 서로 다른 사람의 인증이나 두 머신 시험은 아니다.

| 흐름 | 관찰 결과 |
|---|---|
| 민아 7항목 승인 → 소라 7항목 승인 | 승인 1/2 → 2/2. 다른 탭에서도 SSE로 반영 |
| 준이 실행 요청 저장 | 대기열 증가, `M2 실행기 미연결` 표시, 검증 결과는 미실행 |
| 민아 승인 철회 | 상대 탭에 실행 차단 사유 반영, 대기열에서 제외 |
| API/UI 종료 후 재실행 | 기존 설계·승인·차단 요청 유지, 브라우저 재연결 |
| 게시 전 댓글 작성 → 다른 기능 → 복귀 | 작성 중 댓글 내용 복원 |
| 영수증 설계 수정 후 v2 게시 | v1 유지, 새 해시, 승인 0/2, 이전 버전과 비교 표시 |
| 새 기능 생성 후 빈 템플릿 리뷰 요청 | 7개 항목 초안 생성, 미완성 설계 게시 거절 메시지 |
| 목록 ↔ 보드 | 같은 기능을 설계 상태별로 조회·선택 |
| 밝은/어두운 테마 | 1280×720 브라우저 화면 시각 확인 |

개발 중 HMR에서 createRoot 중복 경고가 관찰되어 App 컴포넌트와 진입점을 분리했다. 재시작/새 탐색 기준으로 검사한다.

## 아직 확인하지 못한 것

- 네이티브 `.app` 실행 파일을 시작했고 프로세스가 유지됨을 확인했다. **네이티브 창 렌더링과 조작은 미검증**이다. CUA가 접근성·화면 기록 권한 대기를 반복 반환했다. 브라우저 화면 확인을 네이티브 앱 검증으로 대체 보고하지 않는다.
- 1024×700 viewport 적용을 요청했지만 실제 DOM은 1280×720을 반환했다. 최소 크기 T13 검증은 통과로 기록하지 않는다.
- 현재 UI 자동화는 이번 작업의 도구 실행 기록이다. 저장소 안에서 재실행하는 Playwright 스위트, CI 실행과 실패 trace 아카이브는 후속 작업이다.
- 서버가 멈춘 동안 다른 클라이언트 쓰기, 전체 프로세스 crash와 장시간 단절, 대규모 이벤트 부하, 성능 p95는 측정하지 않았다.
- M1 역할 거절 테스트는 개발 fixture 계약 시험이다. 실제 인증·프로젝트 접근 제어·두 머신 팀 동기화 T18은 미검증이다.
- M2 대상 T08·T11·T12·T15~17과 M3 대상 T18~20은 현재 제품이 충족한 것으로 표시하지 않는다. T09는 순환 의존과 승인 초기화 부분만 확인했다.
- macOS 공증·실제 로그인·CLI 경로 시험은 하지 않았다. 배포와 사용자 저장소 수정도 하지 않았다.
