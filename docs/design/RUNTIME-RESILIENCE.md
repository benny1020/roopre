# 배포 외 실사용 검증과 실행 복구

사용자 요청: 배포 검증을 제외한 실제 개발 흐름, 동시 작업·장애 복구와 첫 사용 경험을 검증하고 개선한다. 실제 모델·본인 승인과 결정적 fixture 검증을 구분한다.

## 재현한 문제

1. 작업 선택을 위한 DB 읽기가 진행 중일 때 앱을 종료하면, 종료 요청 뒤 새 실행이 시작될 수 있었다.
2. DB 연결 단절 중 실행 종료 상태 저장이 실패하면 재접속해도 작업이 계속 실행 중으로 남아 슬롯을 점유했다.
3. 재시작 시 Docker 정리에 실패하면 실행 관리자 초기화가 실패해 기존 DB의 작업 화면도 열리지 않았다. 취소된 실행을 복구하면서 중단 상태로 바꾸는 문제도 있었다.

세 경로는 변경 전 실패하는 회귀 검사로 재현했다.

## 동작

종료 요청 시 스케줄러를 닫고 진행 중인 스케줄 판정과 실행 종료를 기다린다. 진행 중 DB 읽기가 끝나더라도 새 작업을 시작하지 않는다. 환경 이동 실패 시 종료했던 동일 실행 관리자를 재초기화해 정상적으로 작업을 받을 수 있다.

시작 및 주기적 상태 확인에서 현재 실행기가 소유하지 않는 남은 실행을 정리한다. Docker 컨테이너 종료를 확인한 뒤에만 점유 슬롯을 반환한다. Docker 확인 실패는 10초 이상 간격으로 재시도하며 DB와 작업 화면은 계속 사용할 수 있다. DB 단절로 승인 유효성을 확인할 수 없는 활성 작업은 중단한다. 실행 중 주기적 정리는 작업별 별도 promise로 추적해 느린 Docker 응답이 다른 작업의 취소·승인 확인을 막지 않는다. 같은 작업의 정리를 중복 시작하지 않으며 종료할 때 진행 중 정리도 기다린다.

실행 결과를 받지 못한 에이전트를 완료로 표시하지 않는다. 실행 중 표시는 실패로 정리하고 시각과 이유를 남긴다. 사용자의 취소/승인 철회 상태와 기존 로그·검사·작업 공간은 보존한다. 작업을 자동 재실행하거나 본인 승인을 만들지 않는다. 기존 재시도 명령이 승인 계약을 다시 확인한다.

## 검증 경계

- 단위: 종료 중 DB 응답 지연, DB 재접속 후 남은 상태 정리, Docker 불가 시 시작과 취소 보존.
- Docker/DB/별도 프로세스: 3개 프로젝트·4개 작업의 전역 2개/프로젝트당 1개 점유, 실제 취소, SIGKILL 후 재시작과 체크포인트 재시도, TCP 연결 단절 후 동일 프로세스 복구.
- 실제 Electron: 빈 프로필, 전용 DB 준비, 비밀이 아닌 fixture 연결값의 native 암호화, 실제 Git 프로필 고정, 기본 역할 설정, 첫 기능 생성과 재시작.
- 실제 모델 호출과 사용자의 macOS 본인 승인 성공은 등록된 연결과 사용자 인증 없이는 수행할 수 없다. 이 검증은 fixture 승인 proof를 실제 승인으로 보고하지 않는다.
- 깨끗한 다른 물리 Mac, 배포/서명/공증/업데이트 교체는 이번 배포 제외 요청의 범위 밖이다. 현재 장비의 새 앱 프로필 검증과 구분한다.
