# 설계 보고 확인과 간단 승인

사용자 요청: “본인인증은없애”, “에이전트가 가독성 좋게 정리해서 보고해서 승인받는 느낌”, “간단하게 컨펌”. 이 요청이 이전 macOS 본인 인증 요구를 대체한다. 설계 승인 자체를 없애거나 AI가 자동 승인하도록 허용하는 변경은 아니다.

## 사용자 흐름

에이전트가 요구사항·구조·API/데이터·예외·변경 영향·검증·복구를 보고한다. 사용자는 게시한 설계의 목표, 변경 영향, 검증 계획과 전체 내용을 확인한 뒤 앱에서 승인 또는 수정 요청을 선택한다. 일곱 개 체크박스를 각각 선택하거나 Touch ID/로그인 암호를 입력하지 않는다. 승인과 개발 시작은 별도 동작으로 유지한다.

요약은 게시된 설계 내용에서 가져오며, 실제 생성하지 않은 요약을 AI가 작성했다고 표시하지 않는다. 에이전트의 새 보고서는 핵심 결론부터 짧은 문장·목록으로 작성하도록 요청한다. 요약에서 빠질 수 있는 위험·미해결 사항은 전체 설계에서 확인할 수 있어야 한다.

## 승인 계약

- Electron snapshot은 화면에 표시하는 설계·현재 실행 지침에 대한 binding을 제공한다.
- 사용자가 승인 버튼을 누르면 표시된 설계 ID와 binding을 전달한다. main/domain은 최신 상태와 비교하고 일치할 때 앱 확인 기록을 저장한다.
- 설계 또는 정책이 바뀌었거나 차단 의견이 있으면 승인을 거절한다. 자동 승인·자동 실행은 하지 않는다.
- 승인 기록은 `app-confirmation`으로 표시한다. OS 신원 확인을 수행했다는 의미가 아니다. 기존 `macos-owner` 기록은 기존 승인으로 읽되 binding 변경 시 동일하게 무효화한다.
- 로컬 소유자 권한과 에이전트 승인 금지는 유지한다. 일반 HTTP 미리보기로 실제 소유자 워크스페이스 승인을 허용하지 않는다.
- API 키 암호화와 macOS safeStorage는 유지한다. 제거 대상은 승인 시 요구하던 본인 인증이다.

## 이 저장소의 PR 승인

전담 리뷰와 최신 CI 확인 후 사용자가 승인하거나 머지를 위임한 진행 담당이 검토한 전체 SHA를 `--confirm-head`로 확인한다. macOS 인증 창은 사용하지 않는다. 확인 후 head/base·리뷰 게시물·CI를 다시 검사하고 해당 head만 머지한다. 이 옵션은 OS 인증 증명이 아니며 리뷰 에이전트나 CI가 직접 사용하지 않는다.

## 검증 기준

앱 승인 클릭 → 현재 설계 승인 기록, 수정 요청/철회, 체크박스 없이 확인, 오래된 설계·정책 거절, 에이전트 승인 거절, 차단 의견 유지, 오류 시 화면 보존, 전체 보고서 접근, 기존 승인 읽기 호환을 확인한다. PR 확인 누락·SHA 불일치는 머지하지 않는다. 테스트 fixture 확인과 실제 사용자의 앱 클릭은 구분한다.
