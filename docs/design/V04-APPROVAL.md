# v0.4 하네스 표준 패키지 구현 승인

2026-09-18 사용자 지시: “export / import 기능도 만들고 잘관리할수있게해줘 표준스펙느낌 이해했어? 진행해보자 개발”.

앞선 [하네스 패키지 제안](HARNESS-PACKAGE-PROPOSAL.md)을 바탕으로 표준 계약, 폴더/Git 가져오기, Markdown 편집, 변경 비교, 프로젝트 적용과 폴더 내보내기를 구현한다. JSON + Markdown을 첫 교환 형식으로 사용한다. 회사 공통 지침·프로젝트 프로필·기능 디렉토리·단계 배치·에이전트 정의·필수 검사·한도를 포함하며 실제 인증 정보와 승인 기록은 공유하지 않는다.

기본 표준 선택 시 7개 역할을 제공한다. 기능 범위는 저장소 상대 디렉토리 여러 개이며 기존 단일 Node 패키지 실행 범위를 넓히지 않는다. 적용은 원자적이며 진행 중 작업을 교체하지 않는다. 내용이 바뀌면 새 표준 버전과 설계 재승인이 필요하다. 기존 프로젝트나 팀 전역 정책을 초기화하지 않는다.

이번 구현은 회사 전체 인증/서버 강제, Git 자동 push/업데이트, 별도 registry, 전역 비서 채팅, 진행 매트릭스, 실제 작업 설계 문서의 Git 동기화까지 승인 또는 완료한 것으로 표시하지 않는다. 전용 팀 저장소 생성·게시와 공개 릴리스도 수행하지 않는다. 앱 설치 ZIP은 요청하지 않았으므로 PR에서는 임시 앱 무결성만 검사한다.

구현 승인은 새 PR의 최종 머지 승인과 구분한다. 전담 리뷰와 최신 CI 확인 후 결과를 보고한다. 제품 안의 사용자 본인 설계 승인은 그대로 유지한다. 실제 제공하는 형식과 범위는 [v1 스펙](../specs/HARNESS-V1.md), 검증 결과는 [검증 기록](../VERIFICATION.md)을 따른다.
