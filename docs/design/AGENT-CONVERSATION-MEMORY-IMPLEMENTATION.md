# 개별 대화·기억 구현 기록

기준: [승인 기록](AGENT-CONVERSATION-MEMORY-APPROVAL.md), [고정 설계](AGENT-CONVERSATION-MEMORY.md). 시작 커밋 `d29a9f05b280eb56cafab469a684c74e2d605000`, 작업 브랜치 `codex/agent-conversation-memory`.

현재 상태: 구현 및 로컬 통합 검사 완료, 독립 PR 리뷰 진행 중. 아래 기록은 명시한 검사 범위의 근거이며 실제 모델 품질이나 공개 배포 완료를 의미하지 않는다.

## 구현 경계

- 기억·승인·실행: 프로젝트의 작은 기억 집합, 서버 범위 검증, 조건부 수정, 프로젝트 승인 영향, 고정 실행 입력. Terra 담당.
- 대화·저장·연결: 별도 PostgreSQL 대화 테이블, 범위·용량·중복 요청, 상담 모델 호출, 요약·검색, 삭제·복구·DB 이전. Terra 담당.
- UI: 실행 및 배치 에이전트 선택, 맥락을 보존하는 상담·기억 패널, 입력·실패·재시도, 출처와 승인 영향. Terra 담당.
- 설계·통합 점검·독립 PR 리뷰: Astra. PR 리뷰는 구현 담당과 별도의 고정 커밋 검토다.

공유 계약을 먼저 맞추고 파일 소유권이 겹치지 않게 작업한다. 원문·요약은 전체 snapshot에 추가하지 않는다. 개발 HTTP 경로도 기억 출처 검증을 우회할 수 없도록 Store 트랜잭션에서 검사한다. provider/SQL 원문 오류와 API key는 renderer 오류로 그대로 전달하지 않는다.

## 통합 검토에서 확인하는 실패 경로

대기 요청의 중복 전송이 유료 호출을 두 번 만들지 않는지, 요약이 잘못돼도 유효한 답변을 버리지 않는지, 실패·취소된 턴 때문에 요약 범위가 영구 정지하지 않는지 확인한다. 최근 대화만 전송하면서 이전 기록을 검색했다고 표시하지 않는다. 실제 provider 입력과 맥락 목록을 대조한다.

다른 에이전트로 이동한 뒤 늦은 응답이 새 화면을 덮어쓰지 않게 한다. 원문 삭제·파생 기억 중지는 하나의 트랜잭션이며, DB 이전은 내용 없는 삭제 기록도 보존한다. 종료 상태를 DB에 저장하지 못한 요청은 자동 재전송하지 않고 복구 대상으로 남긴다.

독립 예비 검토에서 시작 시 남은 pending 복구, 이전 중 준비 단계 send의 admission 차단, 실행석 변경 시 상담 대상 갱신, 프로젝트 공통 상담의 기능 실행 참조 제거, 보관된 역할의 기록 열람, 실행 ID·attempt·배치 일치를 확인 대상으로 추가했다. 이 기록은 고정 커밋 PR 리뷰를 대신하지 않는다.

추가 예비 재현에서는 질문 준비 중 대화 삭제·요약 초기화가 완료된 뒤 오래된 맥락이 전송되는 경쟁을 확인했다. 준비 시 읽은 thread ID·revision·summary revision을 요청 생성 트랜잭션에서 비교하고, 일치하지 않으면 모델 호출 전에 거절하는 방식으로 수정했다. 동일 requestId 재조회는 이 검사보다 먼저 처리해 중복 호출 방지를 유지한다. 최종 커밋에서 독립 재현을 다시 확인한다.
