# Quality Intelligence · 0.5 설계

## 결정과 목적

2026-10-01 사용자의 “모두 개선해 완벽하게 해, 이목 끌도록 모두가 관심 있게” 요청을 이번 제품 개선의 구현 위임으로 기록한다. 기존 설계 승인, 격리 실행, 고정 검사, 독립 리뷰와 정확한 head 확인 계약은 유지한다.

루프리는 개발 절차를 표준화하지만 현재 화면은 그 표준이 실제 결과의 품질과 비용에 어떤 영향을 주었는지 보여주지 못한다. 이번 첫 묶음은 저장된 실행 근거를 설명 가능한 지표로 바꾸고, 부족한 근거를 숨기지 않는 Quality Intelligence 화면을 제공한다.

## 확인된 요구

1. 사용자는 여러 프로젝트에서 동일한 Harness가 일관된 품질을 내는지 확인한다.
2. 성공 선언 대신 고정 검사, 리뷰, 비용 보고와 시도 기록을 근거로 사용한다.
3. 프로젝트·Harness revision·최근 실행별 결과를 비교한다.
4. 표본 부족, 비용 미보고, 리뷰나 검사 근거 부족을 정상 성공처럼 표시하지 않는다.
5. 품질 화면에서 해당 기능의 실제 실행·검토 근거로 이동한다.
6. 다크·라이트·1024px 화면, 키보드 탐색과 명확한 텍스트 대비를 유지한다.

## 제품 언어

- `결과 준비`: `ready_for_merge` 또는 `completed`인 구현 실행.
- `실패`: `failed`, `interrupted`, `blocked`인 구현 실행. 사용자가 취소한 실행은 별도로 집계한다.
- `첫 시도 완료`: 결과 준비 실행 중 attempt가 1 이하인 실행.
- `근거 완결`: 결과 준비 실행에 통과한 고정 검사 하나 이상과 비어 있지 않은 독립 리뷰가 모두 존재한다.
- `결과율`: 결과 준비 / (결과 준비 + 실패). 취소·진행·대기는 분모에서 제외한다.
- `보고 비용`: provider가 보고했다고 기록된 유효 비용만 합산한다. 미보고 비용은 0으로 보정하지 않는다.

이 지표들은 코드 품질의 절대 점수나 팀 생산성 보증이 아니다. 화면에 분모와 표본을 함께 표시하며, 결과 표본이 3개 미만이면 `초기 근거`로 표시한다.

## 정보 구조

왼쪽 기본 탐색에 `품질`을 추가한다. 화면은 세 층으로 구성한다.

1. 상단: 선택 프로젝트, 데이터 범위와 근거 신뢰 상태.
2. 핵심 지표: 결과율, 첫 시도 완료, 근거 완결, 보고 비용. 모든 비율에 분자/분모를 표시한다.
3. 설명 가능한 상세: 최근 실행 strip, 프로젝트별 결과, Harness revision별 결과, 보완할 근거.

최근 실행은 장식 차트가 아니라 각 실행 상태·검사·리뷰·시도를 선택할 수 있는 압축된 증거 목록이다. 색만으로 상태를 전달하지 않는다.

## 계산 경계

- planning run은 구현 품질 집계에서 제외한다.
- 동일 Run은 한 번만 집계하고 runtime의 현재 attempt를 사용한다.
- feature의 과거 Run도 실제 실행 기록으로 보존하고 포함한다. 최근 실행 목록은 `run.at`의 유효 시각으로 정렬한다.
- 잘못된 시각, 음수/비유한 비용, runtime 없는 기록은 지표에 억지로 포함하지 않고 보완 항목으로 표시한다.
- Harness 비교 키는 실행 시 고정된 `workflowRevision`; snapshot이 없으면 `기록 없음`으로 구분한다.
- reviewer 문자열 존재만 독립 리뷰의 내용 품질을 보증하지 않는다. 이번 화면은 저장된 근거 존재 여부만 보여준다.

## 인수 기준

- AC01: planning, active, cancelled, successful, failed run이 각 분모에 올바르게 포함/제외된다.
- AC02: 근거 완결은 통과 evidence와 비어 있지 않은 review가 모두 있어야 한다.
- AC03: 비용은 `costReported=true`이고 유효한 값만 합산하며 미보고 수를 따로 표시한다.
- AC04: 프로젝트와 Harness revision별 집계 합계가 전체 필터 결과와 일치한다.
- AC05: 표본 3개 미만, 실행 없음, review/evidence 부족 상태를 명확한 문장으로 표시한다.
- AC06: 최근 실행 선택은 정확한 run ID와 current attempt로 기능 검토 화면을 연다.
- AC07: 홈/작업/품질/에이전트 탐색과 명령 검색, 뒤로/앞으로 복원이 회귀하지 않는다.
- AC08: 다크·라이트·1024px에서 정보가 잘리지 않고 axe A/AA 자동 검사를 통과한다.

## 후속 제품 묶음

이번 화면은 저장된 실행을 읽는 첫 계층이다. 다음 묶음은 순서대로 구현한다.

1. 반복 가능한 평가 Suite와 기준 repository/task fixture.
2. local Docker, macOS sandbox, remote runner를 위한 실행기 adapter 계약.
3. 실제 provider를 이용한 루프리 자체 dogfood와 결과 공개.
4. 팀 SSO/RBAC, 중앙 Harness 배포, 감사와 CI/MR 강제.
5. worktree별 앱·로그·metric·trace를 에이전트가 직접 읽는 검증 환경.

실제 provider 자격 증명, 조직 IdP, 원격 실행 인프라, Apple 배포 인증서 없이 해당 외부 통합이 완료됐다고 표시하지 않는다.
