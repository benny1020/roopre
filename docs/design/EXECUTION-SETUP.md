# 첫 실행 준비와 프로젝트 문맥

## 문제와 개선

여러 프로젝트를 등록한 상태에서 기능의 설정을 열어도 각 화면이 첫 번째 프로젝트를 선택했다. 설정을 끝낸 뒤 원래 기능으로 돌아가는 경로도 분명하지 않았다. 실행 전 빈 화면은 필요한 준비 항목을 안내하지 않아 비활성 버튼의 원인을 찾기 어려웠다.

현재 기능의 프로젝트를 설정으로 전달하고, 설정에서 명시적으로 바꾼 프로젝트는 다른 설정 탭과 새로고침에서도 유지한다. 작업으로 돌아가기는 진입한 기능과 그 기능의 마지막 탭을 복원한다. 저장하지 않은 설정을 자동 저장하지 않는다.

첫 실행 화면은 AI 연결, 저장소·고정 검사, 에이전트 흐름, 설계 검토·본인 승인 네 항목을 목록으로 보여준다. 각 항목에서 해당 설정으로 바로 이동한다. 연결과 실행 프로필은 대상 섹션으로 스크롤하고 키보드 포커스를 옮긴다. 에이전트/공유 표준/프로젝트 지침에서도 같은 프로젝트 문맥을 사용한다.

## 경계

- 설정 안내는 저장된 메타데이터 기준이다. 연결 버전 불일치와 마지막 검사 실패를 구분하며 실제 모델 응답이나 Docker 가용성을 보증하지 않는다.
- 연결 조회 실패는 원문 없이 재확인 경로를 제공한다. API key를 조회하거나 renderer로 전달하지 않는다.
- 요구사항·설계 에이전트 버튼은 실행 프로필과 유효한 계획 역할이 있어야 활성화된다. 최종 실행 검증은 기존 domain/runner가 수행한다.
- 승인/실행/재시도/병렬 처리의 계약과 권한은 변경하지 않는다. 이 화면이 자동으로 승인하거나 모델을 호출하지 않는다.
- 신규 내비게이션 상태만 로컬 저장한다. 설정 전체의 미저장 입력 복원이나 새로운 자동 저장 기능은 이 변경에 포함하지 않는다.

## 검증 기준

두 번째 프로젝트의 기능에서 설정 진입 → 탭 이동 → 다른 프로젝트 선택 → 새로고침 → 원래 기능 복귀를 브라우저에서 확인한다. 다크/라이트·1024px 화면과 axe 검사를 포함한다. 연결 조회 실패의 재시도와 변경된 연결 버전도 검사한다.

격리된 실제 Electron 앱에서는 프로젝트 두 개를 만든 뒤 두 번째 프로젝트의 실행 프로필과 흐름 설정을 연다. 그래프에서 역할을 생성·저장하고 재시작한 뒤 해당 프로젝트에만 저장되었는지 DB로 확인한다. 모델 호출이나 본인 승인 증명을 대체하지 않는다.
