# 루프리 외부 베타 설치 설계안 · 검토용

> 최신 상태: 2026-09-18 [v0.3 구현 승인](V03-APPROVAL.md)을 받고 구현했습니다. 아래 제안 당시 상태는 설계 이력이며, 실제 구현·검증 범위와 남은 조건은 [검증 기록](../VERIFICATION.md)을 따릅니다.

상태: **제안, 사용자 설계 승인 전**. 현재 0.2.1-beta.1의 품질 보강과 별개이며 아래 신규 설치·이전 흐름은 구현하지 않았다. 사용자의 “내가 직접 보고 설계를 승인” 원칙에 따라 이 문서를 검토한 뒤 구현한다.

## 목표와 추천 범위

첫 출시는 소수 개발자의 비공개 macOS 베타를 추천한다. 사용자는 소스 저장소나 Node/pnpm을 설치하지 않고 루프리 앱과 Docker Desktop만으로 시작한다. Docker는 격리 실행에 계속 사용한다. 팀 공유 서버·SSO·자동 업데이트는 후속 설계로 둔다.

핵심 변경은 **앱이 사용자별 PostgreSQL 실행 환경을 준비하고 복구하는 것**이다. 기존 PostgreSQL 도메인·승인·트랜잭션 구조를 유지하여 초기 출시 직전에 저장소 엔진을 교체하지 않는다. 개발용 고정 비밀번호와 공용 localhost 포트 의존성을 제거한다.

## 사용자 흐름

1. 앱은 DB가 없어도 먼저 시작 화면을 표시한다. Git·Docker 실행 상태, 필요한 디스크 공간, 설치 진행 상황을 보여준다.
2. 새 사용자는 “로컬 환경 준비”를 누른다. 네트워크 다운로드와 로컬 컨테이너 생성 범위를 화면에서 확인한 뒤 실행한다. Docker Desktop의 설치·라이선스 동의를 앱이 대신 처리하지 않는다.
3. 루프리가 전용 DB·실행 이미지를 준비한다. 단계별 상태와 실패 원인, 재시도를 보여준다. 사용자가 취소하면 준비 작업을 멈추고 만든 자원과 재개 지점을 기록한다. DB 볼륨은 자동 삭제하지 않는다.
4. 환경 확인 후 AI 연결을 등록한다. 연결 테스트의 과금 가능성을 표시하고 사용자가 실행한다.
5. 프로젝트 선택 → 실행 프로필 → 요구·설계 → **사용자 본인 승인** → 개발을 진행한다. 초기 환경 준비 성공을 설계 승인으로 취급하지 않는다.

## 데이터·실행 구조

- 기존 Electron main + PostgreSQL Store + Docker runner를 유지한다. DB 준비가 끝나기 전에는 프로젝트/실행 명령을 받지 않는 별도 bootstrap 상태를 둔다.
- 프로필마다 충돌하지 않는 DB 컨테이너·볼륨 이름과 무작위 비밀번호를 만든다. localhost에만 동적으로 바인딩하고 실제 포트를 Docker에서 확인한다.
- 비밀번호는 main에서 생성·암호화한다. renderer에는 준비 상태만 전달한다. Docker 준비에 필요한 임시 env 파일은 사용자 전용 권한으로 만들고 사용 후 제거한다. 명령 인자·로그·진단 보고서에 key나 DB URL을 출력하지 않는다.
- 컨테이너 라벨에 앱 ID·프로필 ID를 기록한다. 루프리가 소유하지 않은 DB/컨테이너·볼륨을 수정하거나 지우지 않는다.
- DB/runner 이미지 버전과 bootstrap 단계, 확인된 자원 ID를 로컬 상태로 저장한다. 재시작은 확인→재개 방식이며 동일 버튼을 여러 번 눌러도 중복 자원을 만들지 않는다.
- 같은 OS 사용자와 Docker 관리 권한은 신뢰 경계 안에 둔다. 서로 신뢰하지 않는 팀원/서버 클라이언트를 지원하는 구조는 M3에서 다룬다.

## 기존 데이터 이전

기존 개발 DB나 사용자 기록이 감지되면 자동으로 새 DB로 덮어쓰지 않는다. “기존 환경 유지”와 “백업 후 새 로컬 환경으로 이전”을 구분한다.

이전은 실행 중인 작업이 없고 종료가 확인된 상태에서만 가능하다. 전용 새 DB에 복원한 뒤 워크스페이스 ID·revision·프로젝트/기능/실행 개수와 주요 레코드 해시를 비교한다. 모두 맞을 때만 연결 설정을 전환한다. 실패하거나 중단되면 이전 설정을 유지한다. 원본 DB와 백업을 보존하고 삭제는 별도 명시적 요청이 있을 때만 한다. API key의 다른 Mac 이전은 제공하지 않고 새 Mac에서 재입력을 안내한다.

## 실패·복구와 화면

- 시작 화면: 단계별 카드(필수 도구, DB, 실행 이미지, AI 연결), 준비 버튼, 진행률을 모르면 진행 중 표시, 취소·재시도.
- 실패: 성공 항목은 짧게 표시하고 실패한 단계의 원인과 다음 행동을 자세히 안내한다. raw 로그 전체를 사용자에게 요구하지 않는다.
- 실행 중 Docker 중단: 새 작업 차단, 기존 실행은 종료 미확인 표시. 복구 후 컨테이너 종료 확인을 먼저 수행한다.
- 지원용 진단: 사용자가 미리 보는 버전·준비 상태·정제된 오류 요약만 파일로 저장한다. 자동 업로드하지 않는다.

## 인수 기준

- AC01: DB/Node/pnpm/소스가 없는 지원 Mac에서 앱 시작 화면을 열 수 있다.
- AC02: 준비 두 번 클릭·앱 강제 종료·재시작 후에도 한 프로필당 DB 한 개만 만들어지고 데이터가 보존된다.
- AC03: 고정 DB 비밀번호를 사용하지 않고 LAN 접속을 거절한다. renderer/로그/진단에 비밀번호가 포함되지 않는다.
- AC04: Docker 없음/중단·이미지 다운로드 실패·디스크 부족·포트 변화에서 재시도와 취소가 동작한다.
- AC05: 기존 데이터 이전 검증 실패 시 원본 설정·DB를 유지한다. 성공한 이전 후 프로젝트·설계·실행 근거를 다시 조회한다.
- AC06: 앱 설치부터 실제 provider의 작은 작업 구현·검사·리뷰까지 완료한다. 본인 승인 취소 시 모델 개발 실행을 시작하지 않는다.
- AC07: 서명·공증된 설치본을 다른 Mac에서 설치·재시작·수동 업데이트하고 Keychain/기록의 유지 여부를 확인한다.

## 승인할 결정

1. 첫 외부 범위: 소수 개발자 비공개 베타.
2. 설치 구조: 기존 PostgreSQL을 유지하고 앱이 사용자별 Docker DB를 준비·관리.
3. 데이터 원칙: 기존 환경 유지 선택, 명시적으로 요청한 이전만 수행, 원본·백업 자동 삭제 없음.

Apple Developer 준비 여부와 실제 모델 검증용 연결은 별도 필요하다. 비밀값은 채팅이 아니라 macOS Keychain/루프리 연결 화면에 입력한다. 이 문서를 승인해도 PR 머지나 공개 게시가 자동 승인되는 것은 아니다.
