# 배포 외 실사용 품질 검증

2026-09-22 · 사용자의 “배포검증외에는 너가 다해봐” 요청에 따른 검증. **출시 완료나 완벽한 제품 판정이 아니다.** 실제 유료 모델과 사람 인증이 필요한 항목은 아래처럼 남겨 둔다.

현재 실행 용량은 **전역 작업 2개, 프로젝트당 작업 1개**다. 같은 프로젝트의 다른 기능은 대기하고 단계 내부 에이전트는 최대 3개 병렬이다. 검증 결과를 “같은 프로젝트의 모든 기능이 동시에 실행된다”로 설명하지 않는다.

## 재현해 고친 문제

1. 앱 종료 요청 중 DB 응답이 돌아오면 새 작업을 시작하던 경쟁 상태.
2. DB 장애 중 종료 상태 저장 실패 후 재접속해도 실행 중으로 남던 상태.
3. Docker 정리 실패로 실행 관리자 초기화가 실패해 기존 작업 화면까지 막히던 경로.
4. 종료 확인 과정에서 사용자의 취소 상태를 덮어쓰던 문제와 중단된 에이전트의 실행 중 표시.
5. 종료 확인 전에 재시도 버튼이 활성화되어 실패 요청을 보내던 동선.
6. 검사하지 않은 AI 연결을 준비 완료처럼 표시하던 상태.
7. 온보딩에서 선택한 프로젝트 대신 첫 프로젝트에 개발 기준을 적용하던 문맥 누락.
8. 환경 이동 실패 후 같은 실행 관리자를 다시 시작하면 작업이 영구 대기하던 문제.
9. 남은 컨테이너 정리가 오래 걸리는 동안 다른 실행의 취소·승인 철회 확인이 지연되던 문제. 정리 작업을 분리하고 종료 시 함께 기다린다.

[설계와 경계](design/RUNTIME-RESILIENCE.md). 실행 API와 본인 승인 규칙은 유지한다. 장애 복구는 상태와 리소스를 정리하며 실제 구현을 자동으로 재시작하지 않는다.

## 실제로 확인하지 못한 항목

| 항목                                  | 이유와 필요한 증거                                                                                                                               |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 실제 AI 전체 개발 흐름과 구현 품질    | 사용자 앱에 등록된 모델 연결 없음. 연결 등록·총 비용 한도를 요청함. 실제 요구사항/설계 생성, 본인 승인, 구현·웹 검사·리뷰까지 수행한 기록이 필요 |
| 본인 인증 성공·취소·인증 중 설계 변경 | 사용자 Mac 잠금 상태. 자동화가 사용자 인증/승인을 대신하지 않음. domain의 증명 검사는 실제 사람 인증과 별개                                      |
| 수시간 실제 모델 작업·Mac sleep/wake  | 약 209초의 반복 장애 검증은 장시간 모델 운영을 보증하지 않음. 현재 실행기는 Electron main에 있으며 앱 종료 시 작업을 중단                        |
| 실제 Docker daemon 전체 중단          | 다른 Docker 서비스가 실행 중이므로 전역 데몬을 중단하지 않음. Docker 불가 초기화/정리 실패는 결정적 단위 검사로 확인                             |
| 다른 사람의 첫 사용 이해도            | 현재 장비의 빈 프로필 시나리오와 화면 검토는 수행. 별도 사람 대상 사용성 인터뷰/관찰은 아님                                                      |

모델 응답은 Docker 실행 계약 검사에서 명시적 fixture다. domain 승인 proof 역시 테스트용이며 실제 앱의 사람 인증 성공으로 세지 않는다. 새 온보딩 테스트는 OS 폴더 선택기만 대체하고, 키 암호화와 데이터베이스 생성/저장/복원은 실제 코드를 사용한다. Electron의 새 브라우저 페이지 제한 때문에 native axe는 프레임 없는 화면에 legacy mode를 사용하며, 일반 브라우저 axe는 기본 모드다.

배포/서명/공증/App Store 제출/앱 교체 업데이트/깨끗한 다른 물리 Mac 검증은 이번 요청에서 제외했다. 자동 검사 통과로 이 항목을 대신 표시하지 않는다.

## 재현 명령과 근거

`pnpm check`, `pnpm test:web`, `pnpm test:runner`, `pnpm test:resilience`, `pnpm test:onboarding`, `pnpm test:dogfood`, `pnpm test:desktop`.

로컬 상세 근거는 `artifacts/resilience-*.log`, `artifacts/resilience-results.json`, `artifacts/first-use-results.json`이다. 시각 검토는 `artifacts/recovery-pending.png`, `artifacts/recovery-ready.png`, `artifacts/first-use-environment.png`, `artifacts/first-use-task.png`. 사용자 데이터나 fixture 실행 결과를 앱 기본 데이터로 포함하지 않는다. 전담 PR 리뷰와 최종 CI는 해당 PR의 정확한 커밋을 기준으로 별도 확인한다.
